## 3. Official Judging Rubric (4 Core Pillars)

Submissions are evaluated on a 100-point scale across four core criteria (25% each):

| Pillar | Weight | Evaluation Criteria |
| :--- | :--- | :--- |
| **Technical Implementation** | **25%** | Architecture robustness, codebase quality, functional completeness, Model Context Protocol (MCP) integrations, end-to-end working execution without mocked data. Non-trivial implementation required. |
| **Design & UX** | **25%** | Ergonomics, polish, visual clarity, human-in-the-loop controls, intuitive display of model reasoning and agent state transitions. |
| **Potential Impact** | **25%** | Relevance, market demand, real-world utility, efficiency gains, and tangible problem-solving value. |
| **Idea Quality & Novelty** | **25%** | Originality, thoughtful use of GPT-5.6 Sol and Codex agentic autonomy, avoiding trivial API wrappers or generic chatbots. |

---

## 4. AI Do's & Don'ts (Official Guidance)

* ❌ **Don't Copy-Paste AI Descriptions:** Write project writeups and Devpost descriptions in your own authentic human voice. Judges easily spot LLM copy-paste text.
* ❌ **Don't Use Code You Don't Understand:** A non-trivial, fully functional working implementation is required. Relying on unverified, non-working code will lead to lower scores/rejection.
* ❌ **Don't Let AI Name Your Project:** Avoid generic AI buzzword titles (e.g., *"QuantumFlow AI Assistant Pro"*). Use crisp, memorable, distinct project names (e.g., *"Codex PatchGuard"*).

---

## 5. Mandatory Submission Requirements & Access Rules

To be eligible for judging, every project **must** complete the following before the deadline:

1. **Demo Video (1–3 Minutes):** High-quality walkthrough hosted on **YouTube, Vimeo, or Youku**. Must demonstrate core functionality working live.
2. **Codex Session ID Proof:** Include the exact `/feedback` Codex Session ID from your primary build thread in the documentation/submission page.
3. **Code Repository Access:**
   * Public Repo: GitHub/GitLab link with open-source license.
   * Private Repo (if private): Must grant read access to **`testing@devpost.com`** and **`build-week-event@openai.com`**.
4. **Devpost Setup & Teammates:**
   * Create the Devpost submission page early and save updates.
   * All team members must be invited and accept their Devpost invite before the Tuesday 5:00 PM PT deadline.
5. **Documentation Artifacts:** Comprehensive `README.md`, `AGENTS.md` configuration, `ExecPlans`, and architecture diagrams.
